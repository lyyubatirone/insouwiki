# Les lois de construction d'InsouWiki

## Pourquoi ces lois ?

InsouWiki n'est pas construit uniquement à partir de choix techniques.

Il est construit selon une démarche documentaire dont l'objectif est de garantir que chaque connaissance produite par le logiciel soit explicable, traçable et reproductible.

Ces lois constituent le socle méthodologique du projet.

Elles guident chaque décision de conception et permettent au projet de conserver sa cohérence au fil de son évolution.

---

## Loi n°1 — Le domaine guide toujours le code

Le code ne constitue jamais le point de départ d'une réflexion.

Les objets, les méthodes et les règles métier sont d'abord découverts dans le domaine documentaire avant d'être traduits en logiciel.

Le logiciel n'est que l'expression fidèle du domaine.

---

## Loi n°2 — Aucun concept n'est créé avant d'avoir été découvert

Un objet, un indicateur, une méthode ou une règle documentaire n'est jamais inventé pour répondre à un besoin technique.

Il apparaît parce que son existence a été observée et justifiée dans le patrimoine documentaire ou méthodologique.

La découverte précède toujours l'implémentation.

---

## Loi n°3 — Une méthode documentaire est documentée avant d'être implémentée

Toute méthode documentaire est d'abord définie dans le patrimoine méthodologique.

Sa finalité, ses observations, ses indicateurs, ses limites et son analyse sont décrits avant toute implémentation logicielle.

L'analyseur logiciel n'est que l'implémentation de cette méthode.

---

## Loi n°4 — Un analyseur produit une analyse, jamais une décision

Le rôle d'un analyseur documentaire est d'observer, de qualifier et d'expliquer.

Il produit une analyse documentaire explicable.

La décision appartient toujours au composant qui consomme cette analyse.

Cette séparation garantit la transparence du raisonnement documentaire.

---

## Loi n°5 — Le patrimoine méthodologique est aussi important que le patrimoine documentaire

Le patrimoine documentaire conserve les sources.

Le patrimoine méthodologique conserve la manière de les comprendre.

Ces deux patrimoines sont complémentaires et évoluent conjointement.

Le logiciel assure leur mise en œuvre.

---

## Loi n°6 — Toute décision doit être explicable, traçable et reproductible

Une analyse documentaire ne constitue jamais une boîte noire.

Chaque conclusion doit pouvoir être reliée :

* aux observations réalisées ;
* aux indicateurs identifiés ;
* à la méthode documentaire appliquée.

Le raisonnement doit pouvoir être reproduit à partir des mêmes sources.

---

## Loi n°7 — Un sprint est terminé lorsque le domaine est devenu plus clair

La réussite d'un sprint ne se mesure pas uniquement au nombre de lignes de code écrites ou au nombre de tests réussis.

Un sprint est considéré comme réussi lorsque :

* le domaine est mieux compris qu'au début ;
* le patrimoine méthodologique s'est enrichi ;
* les tests traduisent plus fidèlement cette connaissance ;
* le logiciel est devenu une expression plus fidèle du domaine.

Le code est une conséquence de cette compréhension, jamais son point de départ.
